# 模仿

设计了自己的程序语言 -- meta-lisp，
以及自己的 coding agent -- windbell 之后，
想要设计新的主页来分享这些项目。

想要模仿 Lu 的 xxiivv 主页：

- 首页：https://wiki.xxiivv.com/site/home.html
- 地图：https://wiki.xxiivv.com/site
- 仓库：https://github.com/XXIIVV/oscean

xxiivv 的特点是，导航栏三列，
分别展示一个树状图的：
父与叔节点、兄弟节点、子节点。

这与 ranger 这个文件管理器很相似。
所以我最初想要按照 ranger 的思路来实现。
但是 deepseek 说，不应该考虑文件浏览器，
因为 xxiivv 其实有一个手写的（curated）列表，
`src/tables/lexicon`：

```
0 home
1;audio
2;alicef
3,azolla
2 aliceffekt
3;laeisthic
4 children of bramble
4,known magye
4,extended sleep
3;duomic
4 opal inquisitors
4 portalion
4,dei dain
4,habitants du soleil
```

格式是：

```
<depth><type><name>
```

deepseek 提到了「策展」，
这显然是 curated 和 curation 的翻译。
但是翻译成中文之后，就有了「个人主页的博物馆比喻」。

也就是说，对于个人主页而言，
笔记和文章可能太多且散乱，
不适合直接以「文件浏览」的方式展示。

应该模仿博物馆，来精心挑选展品。

挑选本身就是符号学意义上的解释与叙事。

# 策展

在「博物馆比喻」之下，
我的笔记仓库从代表 inner universe 的 inner，
改名为了 studium，以期与 museum 对仗。

一个笔记仓库的根目录中设置一个 `curation` 文件，
格式如下：

```
<depth> <name> <path>
```

- `<depth>` 和 xxiivv 的设计一样，用以形成树结构。
- `<name>` 是导航所显示的名字也是 url 中 route 的名字。
- `<path>` 是相对于 `curation` 文件的路径，
  指向 markdown 文件，或其他类型的文件。
- 不设置 `<type>` 字段，
  可以根据文件后缀做渲染器分派，
  分派到 markdown 文件的时，
  可以进一步根据 frontmatter 中的 type 字段做进一步分派。
- 为了避免歧义 `<name>` 和 `<path>` 都不能带有空格，
  如果英文需要空格，就用 lisp-case。

设置前端项目：

- [museum.vue] 为模仿 xxiivv 的组件；
- [museum-web.vue] 为使用组件的具体网页。

网站的 URL，模仿 xxiivv 的：

```
wiki.xxiivv.com/site/<name>
```

切合「博物馆比喻」，设计为：

```
museum.xieyuheng.com/exhibits/<name>
```
